So palsync could hand-write a per-pal `.codex/config.toml` directly (bypassing `codex mcp add` entirely) the same way `register.js` hand-writes `.mcp.json` for Claude, achieving real multi-agent parity today without waiting on the upstream `--scoped` flag.

- **The real fix: persist the transient pal id across sessions instead of re-deriving it every time — 2026-09-10**

- **Signed/notarized packaged Mac app: agent console exits with code 1, zero output — found on Mac 2026-09-09, testing the first real signed .app (not `npm run dev`)** — fixed
  Same symptom banner as the earlier "permanently blank/black" fix above (`[agent process exited with code 1]`), but a genuinely different cause underneath, only reachable once the app is actually double-clicked/opened from Finder or `/Applications` rather than run via `npm run dev`. A Mac app launched via LaunchServices (Finder, Dock, `open`) never runs through a login shell, so it never picks up PATH additions from `.zshrc`/`.zprofile`/`.bash_profile` (Homebrew, nvm, etc.) — it gets whatever minimal PATH launchd itself has. Verified by reproducing the exact `agentLaunch.ensureMcpRegistered` + `ptyManager.start` flow against the actual packaged `app.asar` two ways: once via `ELECTRON_RUN_AS_NODE=1 "<app>/Contents/MacOS/<App>" script.js` from a terminal (worked fine — because that inherits the terminal's PATH, which is exactly what made the bug hard to catch), and once by checking the real double-clicked process's live PATH directly, which is where the mismatch actually showed up.

This is the standard fix for the general "Mac GUI apps don't inherit shell PATH" class of problem (same idea as the popular `fix-path`/`shell-path` packages), not something specific to palsync. Verified: simulated the exact restricted LaunchServices PATH via `env -i PATH=/usr/bin:/bin:/usr/sbin:/sbin ...`, confirmed `fixPathSync()` recovers `/opt/homebrew/bin`; rebuilt, reinstalled to `/Applications`, launched via `open` (not a terminal), and confirmed via `ps eww` on the live process that its PATH now includes `/opt/homebrew/bin`.
